## 操作系统 / 进程与线程
进程是资源分配的基本单位，拥有独立地址空间、文件句柄和其他系统资源。线程是 CPU 调度的基本单位，同一进程内的多个线程共享地址空间和打开文件。线程切换通常比进程切换开销更低，但共享内存也会引入同步问题。

## 操作系统 / 同步互斥与信号量
并发程序中多个线程访问共享变量时可能产生竞态条件，因此需要同步和互斥机制。互斥锁保证同一时刻只有一个线程进入临界区，信号量可以描述更一般的资源计数约束。管程把共享数据和操作封装在一起，并通过条件变量实现等待与通知。

## 操作系统 / 死锁与银行家算法
死锁是多个进程因竞争资源而永久等待的状态。死锁产生通常需要互斥、请求并保持、不可剥夺、循环等待四个必要条件。银行家算法通过检查系统是否存在安全序列来决定是否分配资源，从而避免系统进入不安全状态。

## 操作系统 / 虚拟内存与页面置换
虚拟内存通过地址转换让进程获得大于物理内存的逻辑地址空间。缺页中断发生时，操作系统需要从磁盘调入页面；若物理页框不足，则执行页面置换。LRU 页面置换算法优先淘汰最长时间未被访问的页面，适合利用程序局部性。

## 操作系统 / 页表与 TLB
页表保存虚拟页到物理页框的映射，地址转换需要访问页表。TLB 是页表项的高速缓存，可以显著降低地址转换开销。TLB 未命中时需要重新访问页表，若页表项无效还可能触发缺页中断。

## 操作系统 / CPU 调度算法
CPU 调度算法决定就绪进程获得处理器的顺序。先来先服务实现简单但可能导致短作业等待过长；短作业优先能降低平均等待时间但可能造成饥饿；时间片轮转适合分时系统；优先级调度需要处理优先级反转问题。

## 操作系统 / 文件系统与 inode
文件系统负责管理磁盘上的文件、目录和元数据。inode 记录文件权限、大小、时间戳和数据块地址等信息，但通常不直接保存文件名。日志文件系统先记录元数据修改日志，再真正修改磁盘结构，以提高崩溃恢复能力。

## 计算机网络 / TCP 与 UDP
TCP 提供面向连接、可靠、有序的字节流服务，使用确认、重传、滑动窗口和拥塞控制保证可靠传输。UDP 是无连接协议，不保证可靠性和顺序，但头部开销小、延迟低，适合实时音视频、DNS 等场景。

## 计算机网络 / 三次握手与四次挥手
TCP 三次握手用于建立连接，客户端发送 SYN，服务器返回 SYN+ACK，客户端再发送 ACK。三次交互可以确认双方收发能力，并同步初始序列号。连接释放通常需要四次挥手，因为 TCP 是全双工通信，两个方向需要分别关闭。

## 计算机网络 / 拥塞控制与滑动窗口
滑动窗口用于流量控制，使发送方根据接收方窗口限制发送速率。拥塞控制关注网络内部负载，典型算法包括慢启动、拥塞避免、快速重传和快速恢复。拥塞窗口会根据丢包和 ACK 情况动态调整。

## 计算机网络 / DNS 解析过程
DNS 将域名解析为 IP 地址。递归解析中，本地域名服务器会代表客户端逐级查询根域名服务器、顶级域名服务器和权威域名服务器。DNS 缓存可以减少解析延迟，但缓存过期或污染会影响解析结果。

## 计算机网络 / HTTP HTTPS 与 TLS
HTTP 是应用层协议，采用请求响应模型传输超文本资源。HTTPS 在 HTTP 与 TCP 之间加入 TLS，提供身份认证、加密传输和完整性保护。TLS 握手会协商密钥套件并完成证书验证，从而防止窃听和中间人攻击。

## 计算机网络 / IP 路由与 NAT
网络层负责跨网络转发分组，IP 地址标识主机或接口。路由器根据路由表选择下一跳，最长前缀匹配用于确定最具体的路由项。NAT 将内网私有地址映射为公网地址，缓解 IPv4 地址不足，但会影响端到端连接模型。

## 计算机网络 / 子网划分
子网划分通过网络前缀长度把一个地址块拆分为多个更小网络。子网掩码用于区分网络号和主机号。合理的子网设计可以减少广播范围、改进地址管理，并配合路由聚合减少路由表规模。

## 数据库 / 事务与 ACID
事务是数据库中一组逻辑操作的执行单元。ACID 包括原子性、一致性、隔离性和持久性。原子性要求事务内操作要么全部成功要么全部回滚；持久性要求提交后的修改即使系统故障也不能丢失。

## 数据库 / 隔离级别与并发异常
数据库隔离级别包括读未提交、读已提交、可重复读和串行化。较低隔离级别可能出现脏读、不可重复读和幻读。两阶段锁协议通过加锁阶段和解锁阶段约束事务行为，可以保证冲突可串行化。

## 数据库 / 索引与 B+树
B+树是数据库索引的常见结构，所有数据记录通常存放在叶子节点，叶子节点通过链表相连，便于范围查询。与哈希索引相比，B+树更适合排序、范围查询和前缀匹配。

## 数据库 / MVCC 与快照读
MVCC 通过保存数据的多个版本实现并发控制，使读操作不必阻塞写操作。快照读基于事务开始时可见的数据版本返回结果。MVCC 可以减少锁竞争，但需要处理版本回收和可见性判断。

## 数据库 / 范式与函数依赖
函数依赖描述属性之间的决定关系，例如学号可以决定学生姓名。数据库范式用于减少数据冗余和更新异常。第三范式要求非主属性不传递依赖于候选键，BCNF 对决定因素提出更严格约束。

## 数据库 / 关系代数与查询优化
关系代数提供选择、投影、连接、并、差等形式化操作，是 SQL 查询优化的理论基础。查询优化器会根据统计信息选择连接顺序、访问路径和索引使用方式。谓词下推可以尽早过滤无关元组，降低中间结果规模。

## 编译原理 / 词法分析与语法分析
词法分析将源程序字符流转换为 token 序列，识别标识符、关键字、常量和运算符。语法分析根据上下文无关文法检查 token 序列是否符合语法结构，并构造语法树或抽象语法树。

## 编译原理 / 正则表达式 NFA 与 DFA
词法分析器常用正则表达式描述 token 模式。正则表达式可以转换为 NFA，再通过子集构造法转换为 DFA。DFA 在运行时不需要回溯，适合高效识别输入字符流。

## 编译原理 / LL分析与 FIRST FOLLOW 集
LL 分析是一类自顶向下的预测分析方法，需要根据当前非终结符和向前看符号选择产生式。FIRST 集表示符号串可能推导出的首终结符集合，FOLLOW 集表示某非终结符后面可能出现的终结符集合。

## 编译原理 / LR分析
LR分析是一类自底向上的语法分析方法，从左到右扫描输入并构造最右推导的逆过程。LR分析器通常由状态栈、符号栈、ACTION 表和 GOTO 表驱动，能够处理较大范围的上下文无关文法。

## 编译原理 / 语义分析与类型检查
语义分析在语法结构正确后继续检查程序含义，包括变量是否声明、类型是否匹配、函数调用参数是否一致等。符号表保存标识符的类型、作用域和存储位置，是语义分析的重要数据结构。

## 编译原理 / 中间代码与活跃变量
中间代码是介于源语言和目标机器代码之间的表示，常见形式包括三地址码。活跃变量分析是一种数据流分析，用于判断变量值在程序点之后是否还可能被使用，可服务于寄存器分配和死代码删除。

## 编译原理 / 寄存器分配
寄存器分配决定哪些变量保存在有限的物理寄存器中。图着色方法把变量看作节点，若两个变量活跃区间冲突则连边，不能分配同一寄存器。若寄存器不足，需要将部分变量溢出到内存。

## 人工智能 / RAG 检索增强生成
RAG 通过在生成答案前检索外部知识，缓解大模型知识过时和幻觉问题。普通 RAG 常使用向量检索召回相关文本块，但在专业领域可能受到分块、语义漂移和多跳推理影响。

## 人工智能 / BM25 与向量检索
BM25 是经典稀疏检索算法，依赖词项匹配、词频和逆文档频率，适合精确术语查询。向量检索将查询和文档映射到语义空间，适合同义表达和语义相似问题。混合检索常用 RRF 融合两类排序结果。

## 人工智能 / 重排序与 hard negative
重排序模型在初召回结果上进一步判断 query-document 相关性，能提高前几名证据质量。训练重排序器时，hard negative 是表面相似但实际不支持答案的负样本，它能迫使模型学习更细粒度的相关性判断。

## 人工智能 / 知识图谱与 GraphRAG
知识图谱把概念和关系显式建模，可用于扩展多跳检索路径。GraphRAG 将图结构与文本检索结合，适合实体关系密集的领域问答。图扩展可以提高召回率，但也可能引入噪声，需要配合重排序或路径约束。

## 人工智能 / Self-RAG 与反思检索
Self-RAG 强调模型在生成前后判断检索证据是否充分、答案是否被上下文支持，以及是否需要再次检索。反思检索可以降低幻觉风险，尤其适合专业课程中需要引用明确证据的问答任务。

## 人工智能 / RAG 评测指标
RAG 系统常用 Recall@k、MRR、NDCG、Context Precision、Faithfulness 和 Citation Accuracy 等指标评估。Recall@k 衡量是否召回标准证据，MRR 和 NDCG 关注排序质量，Faithfulness 衡量答案是否忠实于上下文。

## 人工智能 / LoRA 与轻量微调
LoRA 通过训练低秩适配矩阵减少大模型微调参数量，适合资源有限的领域适配任务。在 RAG 项目中，轻量微调不一定要直接微调整个生成模型，也可以微调 embedding 模型或 reranker，从而提升检索相关性。
